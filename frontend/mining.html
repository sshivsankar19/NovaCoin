WORKER OPERATIONS

Authenticated mining worker

04

The existing worker requests an authenticated pool job, reconstructs its exact block template, searches a configured nonce range, submits share-target solutions, detects network-valid solutions, and sends heartbeats.

Worker execution is CLI-based. Browser start/stop controls are not exposed by the current API, so this page does not fabricate them.

cd backend
python -m miner.worker --api-base-url http://127.0.0.1:5000 \
  --pool-id <pool-id> --miner-id <miner-id> \
  --miner-address <wallet-address> --api-key <worker-api-key>

IMPLEMENTATION CONTEXT

From transaction to reward

06

Transaction enters the mempool → block data combines the reward transaction with pending transactions → the worker varies the nonce → SHA-256 produces a candidate hash → the hash must satisfy the configured difficulty prefix → a valid block or pool share is submitted → a network-valid pool result records the block and payout.

This describes the implementation currently present in backend/blockchain and backend/miner; it is not a browser simulation or a claim of live hardware mining.
